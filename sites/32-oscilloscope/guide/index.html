An oscilloscope you can patch

01 The idea

25-resonance closed Wing I with a polysynth whose visual was a radial spectrum. This site reuses the "synth you can play" idea but makes the readout an honest XY oscilloscope instead — two oscillators, hard-panned left and right, traced against each other as a Lissajous curve, the way an analog scope in X-Y mode actually works. A Higgsfield video loop of a real modular rack (with a real scope mid-shot showing exactly that kind of curve) sits behind it as the backdrop.

02 The craft

  • Two OscillatorNodes (osc X, osc Y), each through its own gain and a StereoPannerNode panned hard −1/+1, merged with ChannelMergerNode
  • A ChannelSplitterNode pulls the two channels back apart post-merge into two AnalyserNodes so the canvas reads real per-channel time-domain data — this is a genuine two-channel oscilloscope, not a simulated parametric curve
  • Each frame: getFloatTimeDomainData on both analysers, samples paired index-for-index as (x,y) and stroked as one continuous path with a phosphor glow (shadowBlur)
  • Frequency ratio presets (1:1, 1:2, 2:3, 3:4, 4:5) set the classic Lissajous family of shapes; a small "drift" Hz offset keeps the two oscillators very slightly detuned so the pattern slowly rotates instead of locking static
  • Video hero: a 5s Kling loop of a real eurorack + scope, muted/looped/inline, with the still frame as poster and hard fallback

03 Type & color

Space Mono (display) + IBM Plex Mono (body/labels) · near-black #07090a, CRT phosphor green #3dffa0, VU amber #ffae42

04 Reproduce it

  1. Build the audio graph before any user gesture fires it — AudioContext itself must still wait for a click/keypress
  2. Pan two oscillators hard left/right, merge to stereo, then split again to feed two independent analysers
  3. Plot dataX[i] against dataY[i] each frame instead of a single channel against time — that's the whole trick
  4. Fade the canvas each frame with a low-alpha fill instead of a hard clear, for a persistence-of-phosphor trail

05 Iteration notes

  • Build pass: first pass drew a purely mathematical parametric Lissajous curve; switched to real per-channel analyser data so the visual is honestly derived from the audio graph, matching the "driven by a small Web Audio synth" brief rather than faking it alongside the synth.
  • Code-review pass: added a prefers-reduced-motion branch that hides the video entirely (swapping to the static poster image) and replaces the animated requestAnimationFrame trace with a single static parametric curve redrawn only on control change — no continuous animation loop runs at all when reduced motion is requested.
  • Live-browser pass: served locally in headless Chrome; caught that the video element could silently fail to autoplay on some engines even when muted, so added a .catch() that falls back to the still image if play() rejects; confirmed the power-on gate correctly gesture-unlocks the AudioContext on both the boot overlay and the console's Power button.
