FLOWMENU

A nav row that swaps itself for a sliding marquee of its own label — React Bits' "Flowing Menu," hand-rolled

01 The idea

Agency and studio homepages often make the primary nav the homepage: a stack of oversized links is the whole layout. FLOWMENU takes that convention and gives each link a second, hidden identity — an amber marquee band carrying the same word plus a small abstract shape, parked just off the row's edge, that slides in to replace the static label the instant you touch the row. It's staged here as MERIDIAN STUDIO's real nav (Work / About / Services / Contact) rather than an isolated toy, so it's obvious how the same four DOM pieces would drop into an actual site header.

02 How the effect works

  • Two layers per row: a real <a class="row-inner"> nav link sits under a full-bleed .mq-wrap overlay. At rest, .mq-wrap sits at transform:translateY(101%) — one row-height plus 1% below the row, fully hidden by the row's overflow:hidden.
  • Directional entry: on mouseenter, edgeDir() compares the event's Y position against the row's own getBoundingClientRect() midpoint: above the midline returns -1 (enter from top), below returns 1 (enter from bottom). reveal() then snaps .mq-wrap to translateY(±101%) with transition:none, forces a reflow via getBoundingClientRect() so the browser commits that position, then on the next animation frame sets transition:transform .6s cubic-bezier(.16,1,.3,1) and animates to translateY(0%). mouseleave runs the same edgeDir()/animate pair in reverse, so the band always exits toward whichever edge the cursor actually left through.
  • The marquee itself: buildMarquee() fills each row's .mq-track with the row's label + an abstract shape repeated 12 times, twice — two identical halves back to back. A @keyframes mq-scroll animation runs transform:translateX(0) to translateX(-50%) linearly, forever: since the two halves are pixel-identical, the moment it wraps is invisible and it reads as an infinite scroll. Duration lives in the CSS custom property --mq-dur, so speed changes never touch the keyframes.
  • Shapes: each row's swatch is plain CSS — a rotated square (diamond), border-radius:50% (circle), a zero-size box with border triangle trick (triangle), and a 12-point clip-path polygon (plus) — standing in for the "small image" React Bits' version usually shows.

03 Type & color

Unbounded (900 weight, geometric display) for row labels + JetBrains Mono for meta/UI text · near-black #0a0908 · warm amber accent #f2a33c · warm off-white ink #f5efe4

04 The screenshot pass

The whole effect is gated behind mouseenter/focus/touchstart — none of which a headless page load ever fires — so the first render of the site genuinely never showed the marquee at all, just a flat static nav. I added an idle auto-demo that opens row 1 automatically and cycles through the others until a real interaction happens. The first attempt drove it purely with setTimeout, and the desktop and mobile screenshots came back showing two different broken frames: desktop caught the band mid-slide-in (a thin amber sliver at the row's top edge instead of a full band), and mobile caught it mid-slide-out (amber-on-amber unreadable text). The cause: tools/screenshot.js takes a full-page shot after scrolling through the page in steps sized to its height, so desktop and mobile settle at different real elapsed times before the final capture — a fixed millisecond delay could not hit both. The fix was to stop timing it at all: row 1's .mq-wrap now starts with a dedicated .mq-open class set directly in the HTML (transform:translateY(0%) in CSS, no transition), so the band is already fully open at the very first paint regardless of when any script runs, and is held open for 7 seconds — comfortably longer than either viewport's settle time — before the idle demo closes it and moves on.

05 Lift this into your site

To reuse this in another project, copy four pieces:

  • Markup per row: an <li class="row"> containing a .row-inner link and a sibling .mq-wrap > .mq-track div. The row needs position:relative; overflow:hidden; the wrap needs position:absolute; inset:0.
  • Functions to copy verbatim: buildMarquee(row), edgeDir(e, row), reveal(row, dir), hide(row, dir) — none of them reach outside the row they're given, so they drop into any nav structure unchanged.
  • CSS custom property to tweak: --mq-dur (marquee scroll duration) — set it once globally or per-row for varied speeds. Row height, font size and the amber accent are all ordinary CSS you'll want to restyle to match your palette.
  • Gotchas: the transition:none → forced reflow → re-enable-transition sequence in reveal() is load-bearing — skip the reflow and the browser will coalesce the snap and the animation into one, so it slides in from wherever it last was instead of the correct edge. Also wire focus/blur to the same reveal/hide pair for keyboard users, and a touchstart toggle for touch — hover alone leaves touch devices with a dead effect. Respect prefers-reduced-motion by skipping straight to the end state instead of animating the slide.

06 Reproduce it

  1. Build each row as two stacked layers: a real link, and an absolutely-positioned overlay parked at translateY(101%)
  2. On pointer/focus enter, read which half of the row was crossed and snap the overlay to that same edge with no transition
  3. Force a reflow, then re-enable the transition and animate the overlay to translateY(0%)
  4. Fill the overlay with two identical copies of a repeated label + shape, scrolled with a linear 0%→-50% keyframe loop so the seam is invisible
  5. On exit, repeat the edge check and animate back out the same way — never straight to a fixed default
