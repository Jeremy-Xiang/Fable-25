CASSETTE-90

Press play

01 The idea

A Higgsfield-generated product shot of retro hardware sets the mood, blurred into a backdrop rather than used as the interface itself — its knob labels came back slightly garbled (a known generated-text artifact), so the fix wasn't Photoshop, it was design: keep the photo soft and atmospheric, and build the actual, legible, working deck as CSS 3D geometry in front of it.

02 The craft

  • The chassis sits in a perspective wrapper and tilts on rotateX/rotateY as the pointer moves — a real parallax response, not a static image of one
  • Each transport button is a real <button>: :active and a latched .pressed state drop it 4px and collapse its drop-shadow, so PLAY and REC visibly stay down the way a physical deck's buttons do
  • Reels are two nested circles with a repeating-conic-gradient spoke pattern; a CSS animation-play-state toggle starts/stops the spin rather than re-triggering the animation, so it always resumes from its current angle
  • The spectrum readout is a real Web Audio graph — two detuned oscillators through a gain node into an AnalyserNode — drawn to canvas only, never to a hidden audio element, so pressing Stop actually silences it via a gain ramp

03 Type & color

Michroma (display) + Martian Mono (readouts) · near-black chassis #0c0c0d, brushed metal #8f959b, amber CRT #ff9d00

04 Reproduce it

  1. Wrap the deck in a parent with perspective, then rotate the deck itself in response to normalized pointer position ((clientX / width) - 0.5)
  2. Give every button translateZ() to lift it off the panel, and drop both translateZ and box-shadow together on press so the depression reads as physical, not just a color change
  3. Drive the analyser only while a gain node feeding it is actually open, so a "Stop" that silences the gain also stops the visual meter from lying about what's playing
  4. Throttle the canvas redraw loop by timestamp rather than switching between requestAnimationFrame and setTimeout — one persistent loop, one branch on the interval, no risk of the animation silently dying when state changes

05 Iteration passes

  • Build pass — first pass used two separate scheduling paths (rAF while playing, setTimeout while idle) for the spectrum canvas; pressing Play after the page had gone idle never restarted the loop, so the meter froze. Rebuilt as one persistent rAF loop, self-throttled by timestamp
  • Code-review pass — the raw generated hero had legible-but-wrong knob labels; reviewed the composition and moved the photo to a heavily blurred backdrop role instead of a crisp foreground element, so no garbled text ships. Also confirmed every transport control is a real <button>, not a styled <div>, for keyboard operability
  • Live-server pass — served locally, confirmed the deck tilt and reel spin both disable cleanly under prefers-reduced-motion (tilt resets to a fixed 6° rest angle, reels stop entirely, VU throttles to 2fps instead of freezing outright), and checked the mobile breakpoint flattens the 3D tilt and stacks the two screens
