Site 73 · Wave 5 · how it was made

IRONHAND

A desktop you operate with your hand — MediaPipe hand tracking, three gestures, no framework

01 The idea

Commissioned from a reel: a developer controlling his portfolio "Iron Man mode" style — hand in the air, moving app chips around the screen, fist to collect them, sharp pinch to click. The staging here is a desk of launcher chips (a mini portfolio homescreen) so every gesture has something real to act on. The whole thing is one HTML file; the only dependency is MediaPipe's tasks-vision hand landmarker, loaded from a CDN only when the visitor opts into the camera — the page costs nothing extra until then.

02 How the gestures work

MediaPipe returns 21 landmarks per hand per video frame. Every gesture is derived from those points, normalized by hand size so distance from the camera doesn't change the thresholds:

  • Hand size reference: hs = dist(wrist, middle-MCP) (landmarks 0 → 9). Every other measurement divides by this, so "pinch" means the same thing at arm's length and up close.
  • Cursor: the middle-finger MCP (landmark 9), not the fingertip — knuckles barely move when fingers curl, so pointing stays stable through a grab. X is mirrored (1 − x) to match the mirrored preview.
  • Fist: average distance of the four fingertips (8, 12, 16, 20) from the palm centroid, over hs. Open hand reads ~1.6–2.0, fist ~0.7–1.0; the trigger is < 1.05.
  • Sharp pinch: thumb-tip↔index-tip distance over hs. A click fires only on the crossing from open to closed, and only if the hand was clearly open (> 1.5× threshold) within the last 450 ms — that's the "sharp" part. A slow drift into pinch range does nothing, and a fist (where thumb and index are also close) suppresses it.
  • Carrying: while fisted, any chip within the grab radius joins a held stack with a small per-chip offset (a 3-wide grid), and each held chip lerps toward cursor+offset at 0.3/frame. On release every chip gets a random velocity kick and damps out at 0.9/frame — the drop scatters like objects, not files.

Input and rendering are decoupled through one shared state object (S = {tx, ty, fist, pinchNow, seen}). The mouse writes it, or the hand loop writes it; a single requestAnimationFrame tick consumes it either way. That's why mouse mode is a first-class fallback rather than a stub — it exercises the identical grab/click/physics code.

03 Type & color

  • Chakra Petch for display — a squared-off Thai techno face that reads "HUD" without cosplaying sci-fi; JetBrains Mono for labels and readouts.
  • Workshop palette from the source reel: near-black cabin (#0c0909) with a red rim-light wash top-right (#ff4b3e at 13%), arc-reactor cyan (#66e0ff) as the interaction color. Cyan = pointing, red = holding — the reticle and the chip borders both switch, so the current gesture is legible from any distance.
  • The desk is a 44px graph-paper grid over a faint red floor glow; chips are frosted tiles with emoji glyphs (text, not images — the zero-binary-asset rule holds).

04 The screenshot pass

Two real bugs surfaced and were fixed during the critique pass:

  • Phantom hover: the shared gesture state initialized with seen: true, so before any input arrived the chip nearest the stage center rendered pre-highlighted in the very first frame — visible in the desktop screenshot as one glowing chip nobody was pointing at. Fixed by starting seen: false; the hover ring now exists only when a pointer or a hand does.
  • Mobile row squash: the stage had a fixed min-height, but the chip grid is laid out by count — on a 3-column phone layout the fourth row landed below the stage floor, and the per-frame position clamp dragged those chips up into row three, overlapping them. Fixed by sizing the stage from the grid itself (minHeight = top + rows×gap + margin) at layout time.
  • The camera path was verified headlessly with Chrome's --use-fake-device-for-media-stream: model loads from CDN, stream plays, status flips to hand mode, zero console errors. Gesture math was then exercised through mouse mode, which drives the same state machine: hover ring ✓, fist collected 4 chips and carried them ✓, release dropped all ✓, sharp pinch opened the chip under the reticle ✓.

05 Lift this into your site

  • What to copy: the whole <script type="module"> block. The load-bearing parts are the shared state object S, the handLoop() (landmarks → gestures), and the tick() loop (state → cursor/grab/click). The chips are demo furniture — replace them with whatever your interface manipulates.
  • Keep the camera opt-in. Never request getUserMedia on page load — gate it behind a click, import the ~10 MB of WASM + model lazily inside that handler (as here), and leave a pointer path that works without it. On a portfolio, make it an easter-egg toggle, not the default input.
  • DOM contract: a positioned stage container, a reticle element, a <video muted playsinline> + overlay canvas for the preview. Rename the selectors and it drops into any page — React users: mount once inside a useEffect with empty deps and return the stream/RAF teardown.
  • Tunable surface: CFG.smooth (cursor lag vs jitter), CFG.pinch (click sensitivity), CFG.grab (fist reach), the fist threshold (1.05), and the sharp-pinch arm window (450 ms). The live panel wires straight to CFG; hardcode your values and delete it.
  • Gotchas: mirror X once and only once (mirrored <video> via CSS + mirrored cursor via 1−x must agree); normalize every threshold by hand size or the UI only works at one distance from the laptop; suppress pinch-clicks during a fist or every grab fires a click; and don't drive the cursor from the index fingertip — it curls during grabs and the cursor lurches.

06 Reproduce it

  1. Stage a desk: absolutely-positioned chip tiles inside a bordered container, one requestAnimationFrame loop moving them via transform.
  2. Build mouse mode first: pointer position → smoothed cursor, hold → fist, quick click → pinch. Get grab/carry/drop and click feeling right with zero ML in the loop.
  3. Add MediaPipe behind the opt-in button: HandLandmarker in VIDEO mode, one hand, GPU delegate.
  4. Map landmarks to the same state object mouse mode writes. If step 2 was clean, the hand just works.
  5. Tune thresholds against your own hand at two distances from the camera; expose them as sliders while you do.
