TRANSIT

Every route drawn straight

01 The idea

Wing II's asset pipeline runs a Higgsfield-generated image through hand-written HTML/CSS/JS, but TRANSIT inverts the usual ratio: the generated asset — an aged, grain-textured paper background — is deliberately kept in the back seat, and the entire diagram in front of it is drawn algorithmically. Fourteen hub coordinates and one elbow-routing function produce six flat-color subway lines in the Massimo Vignelli tradition: no line was hand-drawn, every 45°/90° jog is computed.

02 The craft

  • A single generated image (aged transit-map paper, subtle grain) sits behind everything at low opacity with mix-blend-mode: multiply and a sepia filter — texture only, never the subject
  • Every line and station is built at runtime from a plain JS object of named hub coordinates (NORTH, UNION, DOCKS, …) and a list of six lines, each just an ordered array of hub keys
  • An elbow-router (routeD) walks each line's points pairwise and inserts a diagonal-then-straight midpoint whenever a segment isn't already purely horizontal, vertical, or 45° — the same convention Vignelli-style diagrams use, generated instead of drafted
  • Stations that appear on more than one line are auto-detected from the hub→line index and rendered as larger interchange rings; single-line stations pick up their line's color automatically
  • Line paths animate in with a classic SVG stroke-dash reveal on load, staggered per line, then respond to hover/focus/click by dimming every other line and station — driven by one shared setActive() function fed by both mouse and keyboard events
  • A small ambient train marker eases along the trunk line's path using getPointAtLength, purely cosmetic motion that's skipped entirely (not just slowed) under prefers-reduced-motion

03 Type & color

Archivo (display/UI) + IBM Plex Mono (labels/legend) · aged paper #efe9db, ink #1c1a17, six flat transit-line hues (red #e4002b, blue #0039a6, green #00933c, orange #ff6319, yellow #c99a00, purple #a626aa)

04 Reproduce it

  1. Define hub coordinates as data, not markup — a plain object mapping a key to [x, y, label]
  2. Define each line as an ordered list of hub keys; build a station→lines index by inverting that list once
  3. Write an elbow-router that only inserts a bend when a segment isn't already axis-aligned or diagonal, so straight runs stay a single clean segment
  4. Render lines and stations into one <svg> with document.createElementNS, tag each with data-line/data-key, and drive all highlight state from those two data attributes
  5. Layer one generated paper-texture image behind the SVG at reduced opacity via mix-blend-mode, gate every animation (dash reveal, train marker) behind a prefers-reduced-motion check

05 Iteration passes

  • Build pass — first draft of the elbow router inserted a bend on every segment including already-diagonal ones, producing visibly wrong double-kinks on the 45° runs; fixed the condition to skip axis-aligned and already-45° segments
  • Code-review pass — confirmed every interactive element (line paths, stations) has a real tabindex/role/aria-label rather than depending on hover alone, checked the legend buttons meet contrast against the paper background at both rest and .on states, and verified the stroke-dash reveal and train marker are both fully skipped (not just slowed) under reduced motion
  • Live-browser pass — served the folder locally, resized down to a phone width and found station labels overlapping at the tightest hub cluster; added a smaller mobile label size and confirmed the legend wraps to multiple rows instead of overflowing, then checked guide/'s relative links resolve correctly back to the site and the collection index from this nested folder
