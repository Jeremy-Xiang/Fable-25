REEL

A draggable inertia gallery, hand-rolled — no scroll-snap CSS, no carousel library

01 The idea

Most "draggable carousel" components on the web are actually native horizontal scroll containers with a drag-to-scroll polyfill bolted on — they inherit the browser's scroll physics, which feels flat and stops dead the moment you release. REEL instead owns the whole motion pipeline: position is a single JS number driven every frame by hand, so the momentum, the infinite wrap, and the snap are all one continuous system instead of three separate hacks glued together.

02 How the effect works

  • Single source of truth: one offset number is applied as translateX(offset) on the track every frame. Nothing else moves the track directly — drag, momentum and snap all just mutate offset.
  • Velocity capture: while dragging, every pointermove pushes a {t, x} sample onto a trailing buffer. On release, velocity is computed only from samples within the last 120ms — v = (x_last − x_first) / (t_last − t_first) in px/ms — so a drag that pauses before release correctly reads as near-zero velocity rather than averaging in stale motion.
  • Momentum integration: each animation frame, velocity *= frictionSlider^(dt/16.67) — a frame-rate-independent exponential decay — then offset += velocity·dt. The Momentum slider (70–98) maps linearly to a per-frame retained fraction of 0.86–0.995; higher retains more speed per frame, so the reel coasts further before stopping.
  • Infinite wrap: the track renders two consecutive copies of the 8 tiles. After every offset change, offset is folded back into the range (−singleSetWidth, 0] by adding/subtracting singleSetWidth. Because copy two is pixel-identical to copy one, the fold is invisible — the reel can be thrown in either direction forever.
  • Snap-to-item: when enabled, once momentum decays below a 0.02px/ms threshold (or immediately on release with zero velocity), offset eases from its current value to Math.round(offset/tileStep)·tileStep over 260ms with an ease-out-cubic curve.
  • Active-tile spotlight: every frame, the tile whose bounding-box center is nearest the reel's horizontal center gets a .active class (lift + gold glow), and a dot indicator below the reel lights up to match — so the loop's position is legible even though the tile set repeats infinitely.

03 Type & color

Bricolage Grotesque (display, 800/600 weight) + IBM Plex Mono (UI/body) · near-black #0a0908 base · gold accent #e0c05a for interactive chrome · each tile gets its own secondary hue (steel blue, rust, sage, lilac, rose, teal, bronze) so the reel reads as varied "projects," not repeated copies.

04 The screenshot pass

The first headless render was clean (no console errors, layout intact on both 1440-wide desktop and 390×844 mobile), so the fix this round was a real gap rather than a visual break: there was no way to tell, from a static screenshot or a quick glance, that the reel contains only 8 unique tiles looping infinitely versus an endless unique set — the "active" spotlight glow on the centered tile was too subtle on its own to communicate position. Added a row of 8 position dots beneath the reel that lights up to match whichever tile is centered, computed from the same nearest-to-center check that drives the spotlight. Also caught and removed a redundant double call to the init routine (it ran once synchronously and again on window.load), which reset offset to 0 twice on load — harmless visually but worth cleaning up since a future edit that seeds a non-zero starting offset would have silently lost it.

05 Lift this into your site

To reuse this in another project, you need three things in the DOM: a .reel container (overflow:hidden; touch-action:none;, focusable via tabindex="0") wrapping a .track flex row, containing your items rendered twice back-to-back (two identical copies — this is what makes the wrap seamless; without the duplication you'd need to reset scroll position at the boundary, which visibly jumps).

  • Copy over: the measure(), normalize(), render(), tick() (the rAF loop), the pointerdown/move/up handlers, and startSnap(). That's the whole engine — everything else (dots, active-glow, panel) is decoration.
  • Constants to tweak: the friction mapping range (0.86–0.995) in the slider handler, the momentum-stop threshold (0.02 px/ms), snap duration (snapDur, 260ms default), and the velocity sample window (120ms) — shorten it for a snappier, more literal "last instant of motion" feel.
  • Gotchas: the container needs touch-action:none or touch drags will fight the page's native vertical scroll. singleSetWidth and tileStep must be re-measured on resize (fixed-px tiles only need this for viewport-driven layout changes; percentage-width tiles need it always). Always respect prefers-reduced-motion — this build zeroes release velocity and jumps instantly on arrow-key nav instead of easing when it's set.

06 Reproduce it

  1. Build a flex track containing your item set rendered twice in a row
  2. On pointerdown, capture the pointer and record a start offset; on pointermove, apply offset = dragStart + dx each frame, folding it back into range
  3. On release, compute velocity from the last ~120ms of samples and hand off to a frame-rate-independent exponential-decay integrator
  4. Once velocity decays past a small threshold, optionally ease to the nearest item boundary
  5. Mirror the same offset math for arrow-key steps so keyboard users get the identical motion, just without the drag
