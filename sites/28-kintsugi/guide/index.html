KINTSUGI

The break is the record

01 The idea

The generated photograph already does the emotional work — a dark stoneware bowl, studio-lit, cracked, sitting on a plinth like a museum object. The site's one job is to make the repair feel like an event rather than a texture: gold seams that aren't part of the photo at all, drawn on top of it in SVG, animate themselves closed the moment the piece scrolls into view. A small "fracture sealed" progress readout underneath ties a second, more literal UI element to the same trigger.

02 The craft

  • Hero: one nano_banana_pro generation, "cracked ceramic tea bowl on a dark wood stand, moody studio lighting, museum photography" — placed inside an aspect-ratio-locked frame so the SVG overlay's coordinate space always matches the rendered image pixel-for-pixel, at any viewport width
  • Six hand-placed bezier crack paths, roughly following the fracture already visible in the generated image, converging on one central break point like the piece really did shatter there
  • Each path's real length is measured at runtime with getTotalLength() and used to set stroke-dasharray/stroke-dashoffset — this makes the "draw-in" animation exact regardless of path shape, no hand-tuned magic numbers
  • An IntersectionObserver fires the repair once, the first time the frame is at least half in view, instead of on page load — so scrolling to it feels like uncovering something
  • A staggered transition-delay per path (main fracture first, branches following) makes the six independent lines read as one continuous gold pour instead of six lines animating in unison
  • The progress bar and "% sealed" counter are driven by the same repair() call as the SVG animation — one trigger, two synchronized effects

03 Type & color

Spectral (display/body serif) + Overpass Mono (labels) · indigo-charcoal #17131f · gold #d9a441 → #f4d998 gradient · warm off-white text #ece6da

04 Reproduce it

  1. Wrap the image in a container locked to the image's exact aspect ratio, then overlay an SVG with a viewBox matching the image's native pixel dimensions — this keeps hand-placed paths aligned across all screen sizes with zero recalculation
  2. For each crack path, read getTotalLength() in JS and set both dash properties from it, rather than estimating the number by eye
  3. Gate the draw-in on an IntersectionObserver instead of page load, so the moment reads as revealed rather than autoplayed
  4. Stagger per-path transition-delay values so a multi-path crack pattern draws as one gesture, main line first
  5. Under prefers-reduced-motion, set every dashoffset straight to 0 and skip the transition and the interval-based counter entirely — the finished state should be immediately visible, not slowly revealed

05 Iteration passes

Build pass: the first crack layout used only one continuous path, which animated as a single unbroken sweep and didn't read as "shattered." Split it into six connected paths with a shared origin point and staggered delays — the branching reads far more like an actual fracture.

Code-review pass: confirmed the gold gradient (#d9a441 on #17131f) and body text (#ece6da on #17131f) both clear AA contrast comfortably. Checked that the repair animation is transform/opacity-adjacent in cost — stroke-dashoffset on six short paths is cheap, no layout thrash — and that the IntersectionObserver callback only ever fires the repair once via a done flag, so re-scrolling the frame in and out doesn't restart it oddly.

Live-browser pass: served locally; on a narrow mobile width the frame's aspect-ratio kept the SVG coordinates aligned correctly, but the placard text below was cramped against the frame — added explicit top margin at the mobile breakpoint. Also caught and fixed a leftover typo in the "why animate it here" copy.
