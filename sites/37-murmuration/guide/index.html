MURMURATION

A flock that thinks as one

01 The idea

Starling murmurations are the classic emergent-behavior demo, but most web versions cap out at a few hundred boids before the frame rate collapses. The goal here was scale: a flock that actually reads as thousands, running smoothly, with a cursor that behaves like a real predator — fear rippling outward through the flock rather than every bird just avoiding the pointer independently.

02 The craft

  • Classic Reynolds boids — separation, alignment, cohesion — but neighbor lookups run through a spatial hash grid (70px cells) instead of checking every boid against every other; that's what makes 1,000+ boids possible on a single thread
  • The cursor is a fourth force: inside its radius, boids steer directly away, scaled by proximity, so nearby birds react hardest — the "ripple" effect is just that reaction propagating through the flock's own alignment rule, not a separate animation
  • A live console (flock size, predator radius, pause) makes the simulation legible instead of a black box — dragging flock size down to ~200 makes the underlying three-rule behavior obvious
  • The generated dusk-sky image was deliberately requested "abstract, not the whole hero" per the brief — a literal photographed flock in the backdrop would visually compete with the live one

What the three passes caught: the build pass found the naive O(n²) neighbor check made 1,200 boids unusable below ~20fps on a mid-range laptop — that's what forced the spatial-grid rewrite. The code-review pass flagged that prefers-reduced-motion was only slowing the animation loop, not stopping it — changed to a hard pause with one static frame drawn on load so reduced-motion users still see the flock's resting shape, not a blank canvas. The live-browser pass found birds spawning outside the fold on ultrawide monitors were invisible until they wrapped around minutes later — tightened the wrap bounds to the actual viewport instead of a fixed constant.

04 Reproduce it

  1. Generate one abstract atmospheric backdrop (nano_banana_pro), optimize with sips, keep it under ~400KB
  2. Implement boids with a spatial hash: bucket entities into a grid each frame, only test neighbors in the 3×3 cell window around each boid
  3. Add a predator force as a fourth steering vector, radius and strength exposed as live controls
  4. Draw each boid as a tiny rotated wedge oriented to its velocity vector — no sprites, just canvas path fills
  5. Gate the whole simulation loop, not just its speed, behind prefers-reduced-motion, and still paint one resting frame
