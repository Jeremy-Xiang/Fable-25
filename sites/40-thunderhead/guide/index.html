THUNDERHEAD

The storm keeps its own time

01 The idea

A generated supercell photograph is dramatic but inert. THUNDERHEAD keeps the photograph honest and puts the motion where it belongs: a canvas lightning generator that builds a genuinely different bolt every time, fires automatically on a random interval, and fires on demand when you click. The strike itself is a screen flash; a beat later, a separate visual pulse stands in for thunder — light first, then everything else, same as the real thing.

02 The craft

  • Bolts are built with recursive mid-point displacement: a straight segment is split at its midpoint, displaced perpendicular to its own direction by a random amount, and the two halves recurse — nine levels deep, displacement shrinking by ~45% each level, so the jitter gets finer as segments get shorter
  • Branches spawn probabilistically partway down the main channel, at reduced depth and displacement, and taper out — most attempted branches die within a level or two, matching how real return-stroke channels actually fork
  • The strike is drawn with additive (lighter) blending and a soft shadow blur, flickered across three quick alpha peaks in ~260ms rather than a single fade, which is what makes it read as electrical rather than as a static glow
  • The screen flash is a full-viewport white div snapped to high opacity then eased back to zero — instant onset, slow decay, the actual shape of a real flash
  • The "rumble" is deliberately not audio (the brief calls for visual-only) — a randomized 350–850ms delay, then either a short sequence of small translate offsets on the whole page wrapper (full motion) or a single brightness pulse (reduced motion)

What the three passes caught: the build pass found the very first branch implementation could recurse indefinitely under certain random branch angles because the branch's own recursion could re-trigger new branches without the probability properly decaying — fixed by halving branch chance on every spawned branch and hard-capping depth. The code-review pass flagged the shake sequence running via nested setTimeout calls with no cleanup, meaning two rapid manual clicks could stack overlapping shakes and leave the page permanently offset — added a guard so a new strike's rumble cancels any shake still in flight. The live-browser pass caught the auto-strike timer not respecting a live change to prefers-reduced-motion (toggling the OS setting mid-session kept the fast interval) — added a change listener on the media query so the interval logic picks up the new preference on the next scheduled cycle.

03 Type & color

Anton + Barlow + Overpass Mono · near-black #0a0912, storm violet-grey #55506a, lavender accent #a49dd9, flash white-violet #eef0ff

04 Reproduce it

  1. Generate one dramatic storm-cell image (nano_banana_pro), optimize with sips, keep it under ~400KB
  2. Write a recursive mid-point-displacement function: split, displace perpendicular, recurse, with a decaying probability of spawning a shorter side branch
  3. Draw with additive blending and a shadow blur for glow; flicker opacity across 2–3 peaks in under 300ms instead of a simple fade
  4. Pair an instant-onset, slow-decay screen flash with a separately-timed, clearly delayed secondary effect so the two read as cause and effect
  5. Listen for live changes to prefers-reduced-motion, not just its value at page load, on anything driven by a recurring timer
