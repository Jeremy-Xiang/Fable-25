CREVASSE

Light, refracted through a thousand years of ice

01 The idea

This is the wing's WebGL showcase for site 29: instead of layering a canvas effect on top of an image element, the generated photograph becomes the shader's own input texture. A single fragment shader samples it with a distorted UV coordinate every frame, which is optically closer to what real ice actually does to light passing through it than any CSS filter could fake.

02 The craft

  • Hero: one nano_banana_pro generation, "glacial ice crevasse interior, crystalline blue-white walls, light entering from above" — uploaded once as a WebGL texture, never touched by CSS
  • Refraction: the fragment shader offsets each pixel's sample coordinate with two slow sine waves (one per axis), scaled by a runtime uIntensity uniform — visually this reads as the ice gently warping the scene behind it
  • Caustics: a compact 3-octave loop of abs(sin·cos) fields, the standard cheap fake for the shifting light-net caustics on a pool floor, tinted glacier-blue and added back into the refracted color rather than replacing it
  • Interaction: cursor position is passed in as a normalized uMouse uniform; a smoothstep falloff around it locally strengthens the distortion, so the ice visibly bends more where you're pointing, like pressing on it
  • A single "Refraction" slider scales uIntensity, which drives both the sine distortion and the caustic brightness together — one real uniform, not a decorative label
  • Graceful fallback: if getContext('webgl') fails, or either shader fails to compile, the canvas is hidden and a plain <img> with a CSS cold-tint filter takes over — the page never blanks

03 Type & color

Outfit (thin geometric display/body) + PT Mono (instrument readouts) · deep glacier blue #0a1a24 · ice cyan #9fe8ff · off-white #eaf6fc

04 Reproduce it

  1. Draw a full-screen quad (two triangles via TRIANGLE_STRIP) with a trivial vertex shader — all the work happens in the fragment shader
  2. Upload the photo as gl.TEXTURE_2D with UNPACK_FLIP_Y_WEBGL = true so its top-left origin matches WebGL's bottom-left texture space without any extra math in the shader
  3. Offset the sampling UV with a couple of cheap sine functions of position and time — this alone reads as refraction
  4. Layer a caustic function (iterated abs(sin(x)*cos(y))) additively for the moving light-net
  5. Pass cursor position and a UI-controlled intensity as uniforms so the effect is genuinely interactive, not baked-in
  6. Always test the "no WebGL" path — hide the canvas, show the raw image, and confirm the page still reads as finished

05 Iteration passes

Build pass: first version distorted the whole frame uniformly, and the ice looked more like a filter than a material. Adding the cursor-local smoothstep falloff — the exact spot you're "touching" refracts more — was what made it feel physically responsive instead of decorative.

Code-review pass: confirmed the animation loop only runs requestAnimationFrame under normal motion settings; under prefers-reduced-motion the time uniform is frozen and the frame is rendered exactly once per relevant event (image load, resize, slider input), so there's no perpetual GPU loop running for a user who asked for less motion. Checked instrument-readout text contrast (#eaf6fc / #a9c4d1 on #0a1a24) — both clear AA.

Live-browser pass: served locally over python3 -m http.server and tested at a narrow width — the right-aligned readout panel collapsed awkwardly under 480px, so the hero text block and stat panel were both given explicit centering/stacking at the mobile breakpoint. Also caught that a failed shader compile (tested by deliberately breaking the GLSL) correctly triggers the fallback image path instead of leaving a blank black canvas.
