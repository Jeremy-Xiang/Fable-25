Site 48 of 50 · how it was made

MURANO

Molten, never still

01 The idea

Wing II mostly leans on Higgsfield-generated imagery, but three sites in this half of the collection (35-orrery, 38-facet, and this one) exist to prove the other Wing II muscle: real, hand-written Three.js 3D with no generated asset in the loop at all. MURANO renders liquid Murano glass — five soft-blended blobs raymarched as a single signed-distance field, refracting and reflecting a synthetic starfield, morphing forever. Drag to orbit it, press and hold to stir its color. Nothing here was photographed, painted, or generated; every pixel is math evaluated live in a fragment shader.

02 The craft

  • A single full-screen triangle/quad is rendered with an orthographic camera; all the actual "3D" happens inside the fragment shader via sphere-tracing (raymarching) against a signed-distance function, not through Three.js's normal mesh pipeline — this is the same technique demoscene/Shadertoy glass scenes use, ported into a THREE.ShaderMaterial
  • The distance field is five spheres orbiting independent Lissajous-style paths, blended with a polynomial smooth-minimum (smin) so they melt into and out of each other instead of ever showing a hard seam — that continuous blending is what reads as "molten" rather than "clustered balls"
  • Surface shading combines a Fresnel term, a refracted sample and a reflected sample of a procedural starfield background (itself just value noise, no texture asset), plus a specular highlight from a fixed key light — four cheap terms stacked instead of a full physically-based glass BSDF, which would have been far more expensive per pixel for a look that reads convincingly as glass anyway
  • Orbit is pointer-drag (with velocity damping toward a target yaw/pitch) or Arrow-key presses on the focused canvas; a faint automatic yaw drift keeps the piece alive when idle so it never looks static on a still screenshot
  • Press-and-hold (pointer or Space) raises a u_stir uniform that brightens the Fresnel rim and nudges the palette's hue offset — a tactile "stir the color" gesture rather than a passive hover effect
  • A try/catch around renderer creation and shader compilation drives a CSS-only fallback: if WebGL is unavailable, the canvas is hidden and a border-radius-morphing gradient blob (@keyframes morph) takes over so the page never shows a blank hole

03 Type & color

Gilda Display (display) + Instrument Sans (UI/body) · void black #050505, Murano fuchsia #c026d3, gold #e8b64a, teal #2adfc2 — a jewel-tone palette pulled from real Murano glass, not from the render itself

04 Reproduce it

  1. Render one full-screen quad with an orthographic camera; do the actual geometry inside the fragment shader
  2. Write a map(p,t) signed-distance function for N moving spheres, combined with a smooth-min so their union has no hard edge
  3. Sphere-trace: step a ray from the camera along rd, shrinking each step by the current distance estimate, until you're within an epsilon of the surface or exceed a max distance
  4. Estimate the surface normal with a small central-difference offset on map(), then compute Fresnel, refraction and reflection against a cheap procedural background function
  5. Gate every animated uniform (time speed, drift) behind prefers-reduced-motion, and wrap renderer/shader setup in try/catch with a non-WebGL CSS fallback so the page degrades instead of breaking

05 Iteration passes

  • Build pass — first draft of the SDF used a hard min() between the five spheres, which produced visible seams where blobs crossed; switched to a smooth-min with a tuned blend radius (k=.55) so the glass reads as one continuous body
  • Code-review pass — the orbit drag had no keyboard equivalent, which would have made the piece unusable without a mouse; added focus styling plus Arrow-key yaw/pitch and Space-to-stir on the canvas. Also found the raymarch loop had no reduced-motion branch for the idle ambient yaw drift (only the shader's own time-scale was gated) — added an explicit check so autoplay rotation stops entirely rather than just slowing down, and confirmed the mobile breakpoint drops the device pixel ratio cap on small screens to keep frame time reasonable
  • Live-server pass — served the folder locally, confirmed the page still renders a coherent scene with the WebGL path force-disabled (CSS fallback blob shows correctly and the direction hint text updates to explain why), verified the canvas has an aria-label describing the interaction for screen-reader users who can't see the shader, and checked guide/'s relative paths resolve back to the site and index correctly from the nested folder
