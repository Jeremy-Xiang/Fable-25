SORT/ED

A pixel-sorting darkroom: luminance runs re-sorted live over a procedural dusk skyline

01 The idea

Kim Asendorf's glitch classic with a lab coat on: within each column (or row), find runs of pixels brighter than a threshold and sort each run by luminance. On a gradient dusk sky the sort tears light into falling streaks; the skyline's windows scatter into them.

02 How it works

  • The negative is procedural: seeded gradient sky, radial sun, parametric skyline with lit windows — NEW NEGATIVE reshoots with a fresh palette.
  • develop() copies the negative's ImageData, walks each line, isolates ≥threshold runs, sorts them (asc/desc), writes back — the original is never mutated, so the threshold slider re-develops losslessly.
  • Direction switches the indexer between row-major and column-major without duplicating the algorithm.

03 Type & color

  • Syne's warped geometry fits glitch; DM Mono for controls.
  • Charcoal bench, amber accent; the art supplies the color.

04 The screenshot pass

  • First render with horizontal default looked barely sorted — a monotonic gradient re-sorted horizontally is a no-op; switched the default to vertical, where the streaking is unmistakable.

05 Lift this into your site

  • develop() works on any ImageData — photos glitch gorgeously; keep the pristine copy and re-sort from it every time or edits compound.
  • Threshold ~0.4–0.55 is the sweet spot on photos; sort the bright runs for light-fall, invert the test for shadow-tear.
  • It's O(pixels·log runlength) — fine on interaction, not per-frame.
