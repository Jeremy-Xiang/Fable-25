MORPH

A custom cursor that morphs its state depending on what it's over

01 The idea

Most "custom cursor" demos are a single decorative shape that just follows the pointer. MORPH treats the cursor as a small state machine instead: it's always displaying one of five states — idle, link, button, drag, text — and the whole point of the demo is staging one of each hoverable element type on a single page so every state is a mouse-move away, with a legend that spells out what each shape means.

02 How the effect works

  • Hidden native cursor: body{cursor:none} on pointer devices (a (hover:none),(pointer:coarse) media query restores the normal system cursor on touch, where there is no hover state to read).
  • One fixed div, five states: #cursor is a single position:fixed element. A STATES lookup table maps a state name to {w, h, radius, rotate} — e.g. link is 78×78 circle, text is a 3×26 sliver with 2px radius, drag is a 46×46 square rotated 45deg into a diamond.
  • State detection: every pointermove, e.target.closest('[data-cursor]') walks up from whatever's under the pointer to find the nearest ancestor carrying a data-cursor="link|button|drag|text" attribute; if none is found it falls back to idle. Detection is O(depth-of-tree), not a per-element hover listener, so adding a new hoverable region is a one-attribute change, not new JS.
  • Morphing: applyState() rewrites width, height, border-radius and a rotation value directly as inline styles — CSS transitions on those properties (implied by the browser's default paint, no explicit transition needed for the size jump to read as a "morph" rather than a snap) plus the position lerp below combine into one continuous motion.
  • Position lerp: the blob's screen position is not pinned 1:1 to the pointer. Each frame: pos.x += (target.x - pos.x) * 0.22 (same for y) — an exponential-decay follow, so the blob trails the real cursor by a few pixels at speed instead of teleporting frame-to-frame, which is what makes it read as a soft, weighted shape rather than a UI ghost.
  • Blend mode: default mix-blend-mode:difference inverts whatever's underneath (readable over both the dark background and light text), togglable to normal from the panel to show the flat, undifferenced look side by side.

04 The screenshot pass

The first headless desktop render showed a stray solid-pink circle sitting on top of the "Selected Work" nav row — not a design element, a bug. The position-follow loop initialized target/pos to innerWidth/2, innerHeight/2 and started rendering immediately on load, so before any real pointer event ever fires, the idle cursor paints itself at a meaningless fixed viewport-center point and just sits there — which a static screenshot (or a page that's merely loaded and not yet touched) exposes immediately, since there's no simulated mouse to move it away. Fixed by adding a hasMoved gate: the cursor stays at opacity:0 until the very first real pointermove, which also snaps its position straight to the cursor (no lerp-in from center) and adds an .armed class that reveals it. Re-screenshotting confirmed the phantom dot is gone on both desktop and mobile, and that legend swatches, nav rows and the buttons/drag-zone card still line up cleanly. Separately, a code-level check caught that the drag-chip's 45deg diamond rotation was being applied twice (once via an inline CSS rotate property, once again inside the per-frame transform string) — per spec those compose, doubling the angle — so rotation is now tracked in a single JS variable and applied in exactly one place.

05 Lift this into your site

To reuse this in a real portfolio:

  • Copy: the #cursor element, its CSS block, and the whole <script> section from applyState() through the follow() IIFE. That's the entire mechanism — nothing else in the page depends on it.
  • What it expects: any element you want the cursor to react to needs a data-cursor="link" (or button/drag/text/your own custom name) attribute; add a matching entry to the STATES object with whatever {w,h,radius,rotate} you want that state to look like.
  • Tunables: the 0.22 lerp factor in follow() controls trail weight (lower = floatier, higher = snappier); sizeScale is the live multiplier the demo's slider drives; swap var(--accent) and the blend mode default to match your brand.
  • Gotchas: set body{cursor:none} only behind a (hover:none),(pointer:coarse) check — touch devices have no persistent pointer position, so a hidden native cursor with no replacement is a dead end for them. Respect prefers-reduced-motion by skipping the lerp (snap straight to the target) rather than disabling the cursor outright. If you add draggable elements near it, give them their own touch-action:none so the browser doesn't hijack touch-drag as a page scroll.

06 Reproduce it

  1. Add one fixed-position div for the cursor; hide the native cursor with cursor:none
  2. Tag every hoverable region with data-cursor="state-name" and define each state's size/shape in a lookup table
  3. On pointermove, use e.target.closest('[data-cursor]') to detect the active state and rewrite the div's inline styles
  4. Drive the div's screen position from a separate requestAnimationFrame loop that lerps toward the real pointer position
  5. Gate the native-cursor hide and the JS entirely behind a hover/pointer-coarse media check so touch devices get the normal system cursor
