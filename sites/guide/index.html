The master guide

How sixty-two websites got built by a language model, in three waves.

Every page in this exhibition — layout, palette, shader, synth patch and copy — was written autonomously by Claude (Fable 5) across three commissions. Wing I (sites 1–25) is a zero-binary-asset flex; Wing II (26–50) is the counterpart, embracing generated imagery, animated video, and real 3D; Wave 3 (51–62) returns to zero assets but adds a real screenshot-critique loop, prompted by a side-by-side look at a different collection. This is the full method for all three, so you can run it yourself.

01 The brief

The original commission: build 25 websites that are fundamentally different from one another, mixing advanced visual techniques — 3D, otherworldly animation, exceptional palettes, novel typography — and put them somewhere public with a guide. The only hard rules were variety, quality, and at least three iteration passes per site before calling it done. A second commission doubled the collection to 50: same rules, but this time explicitly authorizing the generated-imagery pipeline — Pinterest- style reference gathering, Higgsfield stills and video, real WebGL/Three.js 3D — that Wing I had deliberately declined. Twenty-five more rooms, one exhibition, two ways of building a website with a model.

02 Concepting for maximum distance

Twenty-five slots were treated as a spread across axes rather than a list of themes: light vs. dark, serif vs. mono, maximal vs. austere, narrative vs. tool, 2D vs. 3D, code-as-image (shaders, ASCII) vs. image-as-code (SVG scenes). Each site claimed one distinct rendering technology (GLSL, CSS 3D, canvas particles, SVG filters, Web Audio, L-systems, text itself) and one distinct editorial voice — a hotel register, a flight console, a children's book. If two concepts shared either axis, one was replaced.

03 Wing I — the no-asset constraint

Image-generation and video-animation pipelines (GPT Image, Higgsfield/Kling) were available for key assets, and that workflow is legitimate. Sites 01–25 deliberately chose the harder flex: zero binary assets. Every aurora, garment, planet and paper scrap is procedural — gradients, shaders, SVG paths, canvas math. Two reasons:

  • Reproducibility — anyone can view source and own the entire technique.
  • Honesty — nothing on those 25 pages was made by a diffusion model; the design is the code.
The original version of this guide said: "if you adapt this method with generated imagery, the pipeline is gather reference → generate variations → animate → composite as hero assets." Sites 26–50 are that adaptation, built for real. See §04.

04 Wing II — the generated-asset pipeline

A second commission doubled the collection to 50 sites and explicitly authorized the path Wing I declined. The actual pipeline used, per site:

  1. Reference & concept — each of the 25 new sites got a one-paragraph brief (subject, technique, palette, typography direction) written up front so the whole wing could be planned for maximum variety before any generation started.
  2. Generate the still — one hero image per site (skip for the pure-3D pieces), via the Higgsfield MCP, model nano_banana_pro, 16:9, ~2 credits each. Not Pinterest scraping — original diffusion output from a text prompt, in the spirit of "generate similar but different" imagery rather than downloading someone else's photos.
  3. Animate selectively — three sites earned an actual video loop instead of a still (32-oscilloscope, 42-inkwash, 50-eclipse), via Kling 3.0 Turbo through the same MCP, ~7.5 credits each. Video was reserved for places motion was the point, not applied uniformly — cheap doesn't mean free of judgment.
  4. Real 3D where 3D earns it — three sites (35-orrery, 38-facet, 48-murano) are pure Three.js/WebGL with no generated asset at all: procedural materials, real geometry, a real camera. 36-coral and 50-eclipse combine 3D with a generated backdrop. Three.js, loaded from a CDN script tag, is the one dependency exception to Wing I's "no frameworks" rule — justified because it's the actual technology, not a shortcut around writing one.
  5. Composite, don't just paste — every generated still is a layer under or behind a procedural technique (a shader, an SVG overlay, a canvas simulation), the same way Wing I would have built the scene from scratch. The image supplies detail a shader can't; the code supplies motion and interaction a photo can't.
  6. Optimize for the web — raw generations came back at 2–3MB each; every hero image was downsized/recompressed with sips to under ~400KB before shipping. Video assets were kept as delivered and gated behind prefers-reduced-motion, same as Wing I's motion-heavy pages.

Total spend across all 25 generated assets: roughly 85 credits (~20 stills at 2cr, 3 videos at 7.5cr) against a 280-credit balance — image generation turned out to be cheap enough that the real cost was creative judgment, not budget.

05 The build

  1. Each site is still one hand-written index.html — inline CSS and JS. Wing I has zero dependencies beyond Google Fonts; Wing II adds Three.js via CDN for its three pure-3D sites, and a local /assets/hero.jpg (sometimes hero.mp4) per generated-asset site — still no build step, no bundler.
  2. Typography first: one display face chosen per site (50 different families total), then a palette of at most four colors, then layout, then motion.
  3. Motion follows a budget: one signature effect per site executed deeply, plus micro-interactions — never five competing gimmicks.
  4. Accessibility floors everywhere: real headings, keyboard paths, prefers-reduced-motion fallbacks (Wing II also degrades any video/3D to its static image or a CSS fallback under that same media query), data tables behind charts, contrast checked against the actual rendered backgrounds.

06 The iteration passes

Every site went through at least three distinct combs before sign-off:

  1. Build pass — the site is written, then immediately re-read top to bottom for structure, dead weight, and missed opportunities to deepen the concept.
  2. Code review pass — a fine-toothed sweep of the source: contrast ratios, responsive breakpoints, animation performance (transform/opacity only), seeded randomness, resize handlers, reduced-motion branches.
  3. Live browser pass — the site is served locally, screenshotted at desktop and mobile widths, and every interaction is actually driven: buttons clicked, words typed, sliders dragged, synths powered on. Real defects found this way included a hint label colliding with toolbar buttons, a headline losing contrast against a draggable sun, and a nav clipping at phone widths. All fixed and re-verified.

07 Wave 3 — the screenshot-critique loop

After Wings I and II shipped as 50 sites, Jeremy pointed at a different, larger AI-built collection (fable-25.netlify.app — a separate, unrelated project, coincidentally similar name) and said some of its sites looked more polished and smoother. Comparing them directly turned up a real, fixable gap — and Jeremy also said not to spend any more Higgsfield credits on it, which turned out to be the more interesting constraint.

The rival collection's own production notes named the actual differentiator: they render every site headless with Puppeteer, capture a real screenshot at desktop and mobile widths, and do vision-based self-critique on the rendered pixels — not just a re-read of the source. Then they force one deliberate complexity upgrade per site afterward, specifically to stop output from converging toward safe and generic. They also used paid image-to-3D generation for their richest 3D pieces — but the screenshot loop was free, and testing it confirmed it was the bigger lever anyway.

A screenshot harness now lives at tools/screenshot.js in the project root — puppeteer-core driving the system's installed Chrome, zero API cost. It full-page-screenshots a URL at desktop (1440×900) and mobile (390×844), walking the page top to bottom first so scroll-triggered reveals actually fire before capture, and reports console errors and document height. A --thumb mode grabs a single above-the- fold 1280×800 shot for gallery cards.

Twelve new sites (51–62, "Wave 3") were built entirely under this loop: zero Higgsfield calls, zero binary assets, real Three.js and hand-rolled physics/shaders only — proving the polish gap could close without spending anything beyond the time to actually look. The screenshot pass caught real, specific defects across the wave: washed-out lighting that read as a lit floor instead of liquid chrome, a title overlapping a control bar, particles that looked like scattered stars instead of smoke, a hero that read as empty before any interaction, a shading formula that mathematically collapsed to flat binary light/dark, a figure that opened mid-scatter and never read as a figure, a turntable disc that visually clipped through a vessel from the camera's angle, and a bloom pass tuned so hot it blew the frame to solid white. None of these were visible from source alone — they only showed up once the page was actually rendered and looked at.

The gallery you're reading this from also gained a screenshot-based card grid for Wave 3 (real thumbnails, not renders) generated the same way — --thumb against each finished site, converted to compressed JPEG with sips.

08 Deployment

  1. All 62 sites live in one folder as subdirectories — one deploy, one domain, clean paths like /07-phosphor/ and /32-oscilloscope/.
  2. A netlify.toml sets the publish directory; no build command is needed because nothing compiles — Wing II's generated assets are plain static files in each site's own /assets folder, deployed as-is.
  3. netlify deploy --prod ships the folder. The gallery you arrived from is just index.html at the root.
  4. Every site keeps its own /guide route — a page like this one, specific to its techniques.

09 Do it yourself

The honest recipe, any wave: pick concepts that cannot be confused for each other; give each one exactly one signature technique; write the code by hand so you understand every line; then spend as long iterating as you spent building, in a real browser, with a fine-toothed comb. Quality is mostly the third pass. If you're adding generated assets (Wing II's path), spend the same discipline on picking where a still or a video earns its place — the technique still has to be the point, not the image.
