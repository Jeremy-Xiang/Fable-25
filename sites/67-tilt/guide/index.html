TILT

3D pointer-tilt project cards — perspective rotation, moving glare and shadow depth, no library

01 The idea

Component libraries like React Bits sell this as a packaged "tilt card." The point of Wave 4 is to prove it isn't a black box: a card that leans toward your cursor is just three numbers — two rotation angles and a shadow offset — recomputed from pointer position on every move, plus a fourth trick (a repositioned radial gradient) to fake a moving light. TILT stages that in a realistic portfolio grid so it's obvious how the same handful of lines would drop into a real project index.

02 How the effect works

  • Coordinate mapping: on pointermove, the card's getBoundingClientRect() gives x = (clientX-left)/width and y = (clientY-top)/height, each normalized 0–1 across the card.
  • Rotation: rotateX = (0.5-y) * 2 * maxTilt, rotateY = (x-0.5) * 2 * maxTilt. At the card's center (0.5, 0.5) both are 0°; at a corner, both saturate to ± maxTilt. The (0.5-y) sign flip is what makes the top edge tip away from a pointer near the top — the physically correct direction for a surface leaning toward you.
  • Rendering: a perspective parent (.card, perspective:1100px) wraps .card-inner, whose transform is rotateX(var(--rx)) rotateY(var(--ry)) scale(var(--s)) — three CSS custom properties written directly by JS, so the browser's compositor does the actual 3D matrix math every frame, not canvas.
  • Glare: an absolutely-positioned .glare div holds radial-gradient(circle at var(--mx) var(--my), white 0%, white 16%, transparent 42%) with mix-blend-mode:overlay. --mx/--my are set to the same x/y percentages as the tilt, so the "hot spot" tracks the cursor 1:1 — it isn't a separate light simulation, it's the same input reused.
  • Shadow depth: tilt magnitude mag = hypot(rx,ry) / (maxTilt·√2) (0 at center, 1 at a corner) drives both blur and vertical offset of the drop shadow, so a card tilted harder casts a bigger, softer, lower shadow — depth cue reinforcing the rotation instead of a flat constant shadow.
  • Instant-follow vs. spring-back: while the pointer is inside the card, a .tracking class strips the transform transition so rotation follows the cursor with zero lag; on pointerleave the class is removed and a .55s cubic-bezier(.16,1,.3,1) transition eases every value back to 0 — an overshoot-free "settle," not a linear snap.

04 The screenshot pass

The first headless render only ever captures the rest state, so it couldn't show whether the tilt math was actually correct — a card grid that "looks fine" at rest can still have inverted rotation signs or a glare that never appears. I wrote a small puppeteer script that drives page.mouse.move to a point near a card's top-left corner and reads back the live --rx/--ry/--glare-op custom properties plus a cropped screenshot. That caught a real issue: the glare was mathematically firing (opacity ~0.49, correct --mx/--my) but was visually inert — mix-blend-mode:soft-light with a wide 58%-falloff gradient just washed into the thumbnail's existing gradient instead of reading as a distinct highlight. Fixed by tightening the falloff to a hot 16% core fading out by 42%, and switching to mix-blend-mode:overlay for more contrast — the re-shot hover frame shows a clearly legible bright patch riding the corner nearest the cursor.

05 Lift this into your site

To reuse this in another project:

  • Markup: wrap each card in two nested elements — an outer with perspective:1100px (this one doesn't rotate) and an inner .card-inner that receives the transform and contains a sibling .glare div covering it via position:absolute;inset:0.
  • Copy the bindTilt(card) function from index.html verbatim — it's ~25 lines, self-contained, and only assumes the two-element structure above plus the CSS custom properties --rx --ry --mx --my --shadow-y --shadow-blur --glare-op --s.
  • Tunables: state.maxTilt (degrees, try 8–20), state.glare and state.scale (booleans). No other constants need touching — the shadow and glare formulas derive from maxTilt automatically.
  • Gotchas: gate the pointer listeners behind matchMedia('(pointer:fine)') — on touch devices a finger drag over a tilting card fights the page's own scroll gesture, so this build simply doesn't bind the effect there rather than fighting touch-action. Also respect prefers-reduced-motion by skipping the binding entirely so cards stay flat and static rather than looping.

06 Reproduce it

  1. Wrap each card in a perspective parent and an inner transform target, plus an absolutely-positioned glare overlay div
  2. On pointermove, normalize cursor position within the card to 0–1 on both axes
  3. Map that to rotateX/rotateY (inverted on Y) scaled by a max-tilt constant, and to the glare's gradient position
  4. Derive shadow blur/offset from rotation magnitude so depth reinforces the tilt
  5. Strip the transform transition while tracking the pointer; restore it on leave for an eased spring-back to flat
