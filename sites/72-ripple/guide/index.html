RIPPLE

A hand-rolled WebGL liquid-distortion image hover — no shader library

01 The idea

Creative-agency portfolio sites love a hover effect where a project thumbnail seems to be made of liquid — the pointer disturbs it and ripples spread across the image. That effect is almost always a fragment shader distorting texture-sample coordinates, not a real physical simulation. RIPPLE builds exactly that mechanism from scratch: raw WebGL, a hand-written GLSL fragment shader, and a small ring buffer of ripple events, dropped into a four-tile project grid so it reads as a real portfolio component, not an isolated toy.

02 How the effect works

  • Per-tile WebGL context: each .tile gets its own <canvas> and getContext('webgl'), a single fullscreen quad (TRIANGLE_STRIP over 4 vertices), and one texture — a 480×600 canvas-2D composition (gradient + shapes + a speckle noise pass) uploaded once with texImage2D. No binary image assets anywhere.
  • Ripple events: a Float32Array(12*3) ring buffer holds up to 12 concurrent ripples as (u, v, t0) triples in normalized tile-space. pointerdown always adds one; pointermove adds one every ≥45ms so a drag leaves a trail instead of one per pixel.
  • The shader math (GLSL, per ripple i): age = u_time - t0; skip if age<0 or age>3.2. d = uv - center, with d.x *= aspect so the ring stays circular on a non-square tile. dist = length(d). Then wave = sin(dist*40.0 - age*7.5) * exp(-age*u_decay) * exp(-dist/u_radius) — the sin term is a ring that expands outward as age grows (phase depends on dist - age*const), exp(-age*u_decay) fades it out over time, exp(-dist/u_radius) bounds it in space. All active ripples' normalize(d) * wave vectors sum into one offset, scaled by u_strength.
  • Sampling: the final texture read is at uv + offset (clamped so it can't sample outside the texture). A second, smaller offset (offset*0.5) is applied only to the red and blue channel samples — a cheap chromatic-aberration split proportional to local distortion — which is what makes the peak of a ripple read as "glassy" rather than just warped.
  • Controls map directly to shader uniforms: Strength → u_strength (0.03–0.93, displacement magnitude), Decay speed → u_decay (0.4–4.6, how fast exp(-age*decay) kills a ripple), Ripple radius → u_radius (0.08–0.63, the spatial reach in exp(-dist/radius)).

03 Type & color

Space Grotesk (display) + IBM Plex Mono (UI/body) · near-black #05080b→#0a1119 · aqua accent #3fa9f5 · tile compositions vary secondary hue per project (aqua, violet, mint, amber) while the chrome stays monochrome + accent.

04 The screenshot pass

First headless render was correct but static-looking: screenshot.js never moves a pointer, so with the effect only firing on real pointer events, both PNGs showed four flat, undistorted tiles — technically working but demoing nothing, exactly the "canvas is blank because the effect only fires on an event that never happens on load" trap. Fixed by adding an idle-autoplay path: a timer checks now() - lastInteraction > 2.6s and, if true, injects a synthetic ripple into the next tile every ~1.9s at a deterministic pseudo-random point. Any real pointerdown/pointermove resets lastInteraction and autoplay steps back until the visitor stops. Re-screenshotted and confirmed all four tiles now show visibly mid-ripple, expanding rings on both the desktop and mobile capture instead of flat placeholder art.

05 Lift this into your site

To reuse this on a real project grid:

  • Copy the RippleTile class plus the VS/FS shader source strings verbatim — the class expects an element with a single child <canvas> (it reads size from the parent element's getBoundingClientRect(), not the canvas itself, so make the wrapper the sized box).
  • Swap buildTexCanvas() for whatever texture source you actually have — a real photo works too: draw an <img> onto an offscreen canvas (or upload it directly via texImage2D(gl.TEXTURE_2D,0,gl.RGBA,gl.RGBA,gl.UNSIGNED_BYTE,imgEl) once it's loaded) instead of a procedural composition.
  • Tunables live in one place: the params object (strength, decay, radius, each 0–1) — wire them to sliders or just hardcode constants if you don't need a live panel.
  • Gotchas: call resize() on window resize (or a ResizeObserver) or the aspect-correction uniform goes stale and rings turn elliptical; set touch-action: pan-y (not none) on the tile if it sits in a normally-scrollable page, so mobile scrolling still works — pointerdown still fires a ripple on tap even before a scroll gesture takes over; respect prefers-reduced-motion by skipping the requestAnimationFrame loop and autoplay entirely (render one static frame) rather than just slowing it down.

06 Reproduce it

  1. Give each tile its own canvas + WebGL context and upload one texture (procedural or a real image)
  2. On pointer events, push (u, v, timestamp) ripple records into a small fixed-size ring buffer
  3. In the fragment shader, sum every active ripple's sin(dist*freq − age*speed) · exp(−age·decay) · exp(−dist/radius) into a UV offset
  4. Sample the texture at uv + offset, splitting R/B channels by a fraction of that offset for a chromatic-aberration edge
  5. Add an idle-autoplay fallback so the effect is visibly demonstrating itself even before anyone touches it
