HOLOTYPE

Light that only exists at this angle

01 The idea

Wing II's pipeline runs a Higgsfield-generated image through hand-written HTML/CSS/JS, no frameworks or build step. HOLOTYPE takes that pipeline toward physical-object simulation: a single generated holographic-foil texture becomes the art on a trading card that behaves like foil actually behaves — its rainbow sheen shifts with viewing angle, not with time, because real foil doesn't animate on its own, it only reacts to how you're looking at it.

02 The craft

  • One generated hero asset: an iridescent rainbow foil texture on black, used as the card's base image layer
  • The holo sheen is a conic-gradient (magenta → gold → mint → cyan → violet) whose start angle and center point are CSS custom properties driven live by pointer position, blended onto the image with mix-blend-mode: color-dodge so bright image pixels bloom with color and dark pixels stay dark
  • A second, fainter overlay of thin diagonal lines at mix-blend-mode: overlay shifts horizontally with the same pointer input, standing in for the fine line-diffraction texture real foil stock has
  • A soft radial glare tracks the same coordinates at mix-blend-mode: soft-light, reinforcing the sense of a light source moving across a glossy surface
  • The card itself sits in a perspective stage and rotates on both axes based on pointer offset from its own center, not the viewport's, so it tilts the way an object tilts in your hand rather than swinging around a fixed page point
  • All numeric targets (rotation, gradient angle, glare position) are eased toward on every frame rather than snapped to, which is what keeps the tilt feeling weighted instead of jittery

03 Type & color

04 Reproduce it

  1. Build the card as a perspective container holding a stack of absolutely-positioned layers: image, holo gradient, fine-line overlay, glare, border — all sharing the same border-radius
  2. On pointermove, compute the cursor's position relative to the card's own bounding rect (0–1 on each axis), not the window, and derive rotation, gradient angle, and glare center from that single pair of numbers
  3. Ease every driven value toward its target each animation frame (v += (target - v) * 0.12) instead of assigning directly, so the tilt settles rather than snapping
  4. Mirror the same pointer-position math from deviceorientation beta/gamma on touch devices, gated behind an explicit "enable tilt" tap since iOS requires a user gesture before granting motion permission
  5. Give the card tabindex="0" and arrow-key handlers that nudge the same rotation targets, so the whole effect is reachable without a pointer

05 Iteration notes

  • Build pass: first draft rotated the card around the viewport's center, which made the tilt feel like the whole page was warping rather than one object turning; switched to computing pointer offset from the card's own bounding rect and the tilt immediately read as physical
  • Code-review pass: checked dim-text-on-black contrast for the body copy, confirmed the reduced-motion branch fully skips the requestAnimationFrame loop rather than just slowing it (so a reduced-motion visitor gets a static, centered holo card, not a subtle animation), and added an explicit keyboard path (arrow keys + Escape to reset) since the base interaction is pointer/gyroscope only
  • Live-browser pass: served locally and tested pointer drag across the card — caught that fast cursor movement briefly showed a jittery gradient because the angle variable wasn't wrapping past 360°, fixed by keeping the angle formula bounded to a small range rather than accumulating; also confirmed the gyroscope permission button only appears on touch devices, since deviceorientation is meaningless on desktop
