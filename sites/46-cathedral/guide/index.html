CATHEDRAL

Light through lead

01 The idea

CATHEDRAL is the first site of Wing II, the half of this collection that embraces generated imagery instead of avoiding it. A Higgsfield-generated stained-glass window is the hero — but it isn't just a backdrop. An SVG "lead came" network is algorithmically re-drawn over it on every load, so the window always looks freshly leaded, and a light-ray sweep drifts across the glass on its own until you take the wheel.

02 The craft

  • The hero image is a real photo-realistic generated asset (assets/hero.jpg), optimized with sips before shipping — the raw Higgsfield export was actually a PNG saved with a .jpg extension, so the build pass had to force a true JPEG re-encode rather than trust the file suffix
  • The lead lines are not traced by hand: a recursive rectangular subdivision (à la a jittered treemap) generates an irregular cell lattice, each dividing line bowed slightly with a quadratic curve so it reads as hand-worked lead, not a ruler line
  • Six pointed-arch paths are layered on top, echoing the arches already present in the photo so the generative layer and the photo's own architecture agree with each other
  • Every line self-draws via stroke-dasharray/stroke-dashoffset, staggered by index, once per load
  • The light sweep is a skewed gradient positioned by a CSS custom property (--lightpos), driven by pointer position, a slow autoplay drift, or a native <input type="range"> for keyboard and touch users — the same variable feeds all three input paths so they never fight each other

03 Type & color

Almendra SC (display) + Source Serif 4 (body) · stone-grey #211f1c, lead-gold #caa23a, with sapphire/ruby/emerald sampled from the window itself

04 Reproduce it

  1. Recursively split a rectangle into cells (random split axis, 32–68% position), stopping below a minimum size — this is the whole "generative tracery" trick
  2. Bow each dividing line with a quadratic Bézier control point offset by a few pixels, chosen once per line, not per frame
  3. Animate each path's own length via getTotalLength() so the stroke draws itself in regardless of path shape
  4. Drive one CSS variable from three input sources (pointer, autoplay loop, range input) rather than writing three separate animation systems

05 Iteration passes

  • Build pass — first version of the subdivision produced lines so dense at high depth that the photo underneath disappeared; capped recursion at depth 5 and raised the minimum cell size to 70px
  • Code-review pass — caught that the light-ray gradient at full opacity blew out contrast on the hero copy; added a scrim gradient beneath the text and dropped ray opacity/blend mode to screen at .55; also caught the reduced-motion branch skipping the draw-in animation but forgetting to strip the CSS transition itself, which still fired a 1s fade — fixed by gating the whole animation setup, not just the RAF trigger
  • Live-server pass — served the folder locally, confirmed assets/hero.jpg and both font families load with correct paths from a nested guide/ directory, verified the slider is reachable by Tab and its label is announced, and checked the mobile breakpoint hides the hint text so the control panel doesn't wrap awkwardly on narrow screens
