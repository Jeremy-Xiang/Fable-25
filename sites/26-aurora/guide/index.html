AURORA

A sky that keeps painting itself

01 The idea

Wing II's whole premise is generated imagery plus a procedural layer that a photo alone can't provide: motion. AURORA is the clearest test case — a still painting of the northern lights is beautiful but static, and the northern lights are anything but. So the image stays exactly as generated, full-bleed and untouched, and a live flow field paints new ribbons in the same three hues directly on top of it, in front of the mountains, behind nothing. The photo supplies the texture a canvas gradient never could; the canvas supplies the one thing the photo structurally cannot: continuous, non-repeating motion.

A "solar wind" slider ties the metaphor to the mechanism instead of leaving it decorative — dragging it changes the actual noise-sampling rate and step size the flow field uses, so the sky visibly goes from a slow drift (Kp 2, calm) to a rough, fast churn (Kp 9, severe storm), which is also roughly how a real geomagnetic storm looks against Earth's aurora oval.

02 The craft

  • Hero: one nano_banana_pro generation, "painterly cinematic aurora borealis over dark silhouetted mountains, teal-violet-green, snowfield foreground, stars" — used as a fixed, full-bleed backdrop image, no CSS filters beyond a slight saturation/brightness trim for legibility
  • Motion layer: a transparent canvas positioned over the image with mix-blend-mode: screen, so painted strands add light onto the photo rather than covering it
  • Flow field: a small hand-written 2D value-noise function (hashed lattice + smoothstep interpolation — no external noise library, keeping the "one dependency: Google Fonts" rule) drives a per-frame angle for ~220 short-lived particles; each is retired and reseeded near the top of frame once its life or bounds run out, which keeps the ribbon density even instead of clumping
  • Color: three fixed RGB triples matching the painting's palette (oxygen teal, nitrogen violet, high-altitude green), each strand picks one at spawn so the canvas layer reads as an extension of the image's own hues, not a foreign overlay
  • Trail fade via destination-out compositing at low alpha each frame instead of a solid fillRect — avoids ever showing a hard rectangle edge against the transparent canvas
  • Below the fold: a two-column field-notes section (why the image and the shader split the labor) plus a small legend explaining the physical basis of each of the three colors, so the page has real content beyond the hero, not just a full-bleed image with a headline

03 Type & color

Bricolage Grotesque (display) + Red Hat Mono (labels/mono) · near-black blue #050b12 · teal #4fd7c4 · violet #8f6bff · green #6fffa8 · ice-white text #dbeeff

04 Reproduce it

  1. Place the generated image as a fixed, full-bleed <img> behind everything, then a same-size transparent <canvas> directly on top with mix-blend-mode:screen
  2. Write a minimal value-noise function — hash two integers to a pseudo-random float, bilinear-interpolate the four lattice corners with smoothstep easing
  3. Give each particle a noise-derived heading each frame, step it forward, stroke a short segment in a hue sampled from the source image's own palette
  4. Fade old trails with a low-alpha destination-out rect instead of clearing the canvas outright, so strands trail rather than blink
  5. Wire one control (here: a slider) to the noise sampling rate and step length so "intensity" is mechanically real, not just a label

05 Iteration passes

Build pass: first draft had the flow field covering the full viewport including the darkest lower third of the image, which muddied the mountains — clipped the particle spawn band to the upper ~60% (sky only) so the silhouette stays clean and readable. Added the field-notes section below the fold after realizing the first draft was hero-only and read as a single gimmick rather than a page.

Code-review pass: checked contrast of the ice-white body text (#dbeeff) against #050b12 — comfortably AA for the size used. Switched the trail-fade from a full clearRect to alpha-based destination-out for smoother motion at effectively the same per-frame cost (still just two canvas ops). Confirmed the slider and every link are reachable and operable by keyboard alone (native range input + anchor tags, no custom widgets that trap focus).

Live-browser pass: served locally and watched the canvas at both low and high "solar wind" settings — at 100 the strands were flickering distractingly fast, so the speed formula was reworked to scale the noise-time increment rather than the frame's redraw rate, which keeps it fast but readable. Confirmed prefers-reduced-motion fully halts the particle system (N set to 0, single static clear) rather than merely slowing it, per the brief's "gracefully degrade" requirement.
